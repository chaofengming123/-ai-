# 第 24 课：文本分块，观察块大小、重叠与段落边界

上一课可以从文档提取文字。本课把文字切成多个片段，并在文档管理中提供“分块预览”。你可以修改块大小和目标重叠长度，观察每块内容以及相邻块重复了哪一段。

这是 RAG 文档处理中的 Chunk 步骤。目前只预览，不保存分块、不调用 Embedding，也不把文档交给 GLM。

## 一、先做一个分块实验

重启新版后端，保持前端运行。在“文档管理”选择知识库，对一个文档点击“分块预览”。没有合适材料时，可以上传仓库中的 [分块实验材料](samples/chunking-demo.md)。

macOS 在项目根目录分别启动后端和前端：

```sh
scripts/backend.sh spring-boot:run
npm run dev --prefix frontend
```

只运行一份后端，避免 8080 冲突。Windows 与 IDEA 启动方式继续参考第二十一课。本课不需要新增模型 Key 或启动新数据库服务。

依次尝试：

| 块大小上限 | 目标重叠 | 观察重点 |
| --- | --- | --- |
| 300 | 0 | 块数、块尾是否把一句话切开 |
| 300 | 50 | 第二块开始是否保留了上一块的部分信息 |
| 500 | 50 | 一个块能否更完整地表达一个主题 |
| 800 | 50 | 块数是否减少，是否混入更多主题 |

每次改完参数点击“重新分块”。结果区显示的是生成该结果时实际使用的参数，不是尚未提交的表单值。前面三块默认展开，其余可以点击查看；黄色文字是与上一块重叠的部分。

## 二、为什么要把文字切成块

假设一份文档有几十页，包含上传、登录和部署三个主题。用户问上传问题时，我们希望检索出最相关的几个片段，再把这些片段交给模型。

块太小，单独看可能缺少前提；块太大，可能包含很多无关内容。分块的目标是形成适合检索和提供上下文的单位，不能只用“块数越多”判断效果好坏。

本课还没有实现检索，因此只能观察可读性、边界与重复量。哪组参数能提高检索效果，要等接入 Embedding 和检索后，用实际问题验证。

## 三、字符与 token 先分清

本课块大小按 Java String / JavaScript 的 UTF-16 长度计算。常见汉字通常占一个单位，emoji 可能占两个；它不是字节数，也不是模型 token 数。

学习手册后续会讨论 token 预算。当前先用不依赖具体模型的字符分块理解基本流程；不能把这里的 500 字符直接称为 500 token。接入 Embedding 后，还需要按所选模型的输入限制检查或调整分块策略。

## 四、后端接口与请求顺序

新增接口：

```text
GET /api/documents/{id}/chunks?size=500&overlap=50
```

默认块上限 500，目标重叠 50。参数限制是：块大小 200–2000；重叠 0–200，且小于块大小的一半。参数必须是整数。

```text
Vue 提交文档 ID 和参数
 → Axios 附带本项目 JWT
 → Spring Security 检查 document:read
 → DocumentController.chunks()
 → DocumentService.chunks() 先校验参数
 → 复用 preview() 读取文件、提取受限正文
 → TextChunker.split() 生成片段
 ← ChunkPreview Java 对象转成 JSON
 ← Vue 展示片段、高亮和来源范围说明
```

参数不合法返回 400；未登录 401；无查看权限 403；文档不存在 404；解析繁忙沿用上一课的 503。正文预览和分块预览共用两个解析名额，没有绕过文件读取与格式校验。

## 五、TextChunker 如何切分

关键文件：`backend/src/main/java/com/example/aiknowledge/service/TextChunker.java`。

```java
public record Chunk(int index, int startOffset, int endOffset,
                    int overlap, String text) {}
```

index 是从 0 开始的块编号。startOffset 和 endOffset 是在提取后正文中的范围，采用左闭右开区间；text 必须等于 `source.substring(startOffset, endOffset)`。这些偏移不是原始文件的字节位置，也不是 PDF 页码。

### 第一步：确定窗口上限

```java
int end = Math.min(text.length(), start + size);
```

从 start 出发，最多取 size 个 UTF-16 单位。如果剩余文字已经不足一块，就直接取到末尾。

### 第二步：寻找比较自然的结束位置

本课在窗口后 40% 的范围内，依次寻找段落空行、换行、句末标点、分号和空格。某一类分隔符存在时，采用该类在窗口内最后出现的位置，并把分隔符保留在当前块末尾。

```java
int minimum = start + size * 3 / 5;
```

例如块上限是 200，就只考虑距离起点至少 120 的边界。这样即使开头有一个很短的段落，也不会为了它把一个大窗口切成非常短的一块。找不到合适边界时按上限切开。

这是一套明确、可观察的规则，不是模型理解语义后决定边界。句号也可能出现在缩写或编号中，所以本课的启发式规则并不保证每块都是完整句子。

### 第三步：保留原文片段

```java
text.substring(start, end)
```

片段不做 trim，不改写原句，也不让模型生成摘要。保留空格与换行，才能准确对应正文偏移，并验证有没有漏字。

### 第四步：计算下一块的起点

```java
start = end - overlap;
```

当块上限为 200、目标重叠为 50，且没有提前遇到自然边界时，范围类似：

```text
第一块：[  0, 200)
第二块：[150, 350)
第三块：[300, 500)
```

第一块末尾的 [150, 200) 会出现在第二块开头。重叠使边界附近的文字在两个检索单位中都能被看到，但也增加了重复内容。

因为自然边界可能提前结束，实际块长通常不完全等于上限。因为 emoji 需要完整代理对，实际重叠也可能比目标少一个单位，接口因此逐块返回实际 overlap。

## 六、怎样避免漏字、乱码和不前进

块结束位置如果落在一个 emoji 的代理对中间，就向左移一位，完整字符留到下一块。下一块起点如果落在代理对后半部分，就向右移一位，减少这一处实际重叠。

重叠限制为小于块大小一半，而自然边界只选在窗口后 40%，保证每次有新的正文进入结果。不会不断生成同一块。

测试采用一个重要检查：依次拼接每块去掉实际重叠后的文字，应当还原原始正文。它比只检查“生成了几块”更有意义，因为能发现丢字、重复计算错误和偏移不一致。

空白正文返回零块，短正文返回一块。分块器只接受上一课限制内、最多 40000 字符的文本，不允许通过这个接口提交任意长度的字符串。

## 七、正文范围限制必须继续传到页面

`DocumentService.ChunkPreview` 包含：

- `sourceCharacters`：本次用于分块的正文长度。
- `sourceTruncated`：正文是否已因页数或字符上限被截断。
- `note`：沿用提取器对 PDF、DOCX 等格式的说明。
- `chunkSize` / `overlap`：本次实际使用的参数。
- `chunks`：片段列表。

如果一个 PDF 有 100 页，本课仍只提取前 20 页并生成这些文字的分块。页面会提示分块只覆盖已提取部分。不能把这份预览结果标记为“整份文档已索引”。

没有新增 MySQL 表、Flyway 迁移或向量存储。原文件和 UPLOADED 状态保持不变，每次重新分块都会重新提取正文。正式入库时需要单独设计完整处理流程与失败状态。

## 八、Vue 组件如何工作

新增组件：`frontend/src/components/DocumentChunkPreview.vue`。

父页面将选中的文档作为 prop 传入，组件用 ref 保存参数表单。挂载时按默认参数请求一次，点击“重新分块”后用新参数再请求。

前端校验让用户及时看到输入问题，后端校验仍然必须保留，不能信任浏览器已经校验过。

请求管理复用上一课的 `createDocumentPreview()`：切换预览会取消旧请求，通过 generation 和 sessionVersion 丢弃迟到结果。父组件用文档 ID 作为 key，切换文档时销毁旧分块组件；关闭预览或切换知识库也会卸载它。

高亮的核心是：

```vue
<mark>{{ chunk.text.slice(0, chunk.overlap) }}</mark>
{{ chunk.text.slice(chunk.overlap) }}
```

前半段是与上一块重复的原文，后半段是新增内容。实际模板只在 overlap 大于零时显示 mark，并放在保留换行的 pre 中。所有内容用 Vue 插值显示，不执行文档里的 HTML。

## 九、本课验证与练习

测试覆盖固定窗口、优先段落边界、重叠与偏移、短文本与空白输入、参数拒绝，以及中文和 emoji 在多种块大小下的完整还原。接口测试验证权限、无效参数、缺失文档、原文件不变、正文截断标记；前端测试确认参数传递和旧请求不会覆盖新结果。
