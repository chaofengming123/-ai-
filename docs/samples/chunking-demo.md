# 文本分块实验材料

这是一份专门用于第二十四课的练习文档，不是真实企业制度。请先把它上传到测试知识库，再分别使用三百、五百和八百字符的块大小观察分块结果。观察时不要只数有多少块，还要阅读每块的开头和结尾，判断它是否包含一个相对完整的意思。文字被切成小块之后，人仍然应该能看懂每块在说什么。

## 文档上传与原文件

用户上传文件时，前端把文件和所属知识库编号一起发送给后端。后端先检查文件名、大小和内容格式，再将原始字节保存到文件存储中，并在数据库中记录文件名、大小和存储位置。原文件用于下载和重新处理，所以正文提取与分块预览都不应该改写原文件。即使我们以后改变分块策略，也应当能够从保留的原始文件重新开始处理。

## 正文提取与格式差异

TXT 和 Markdown 可以直接按照指定编码读取；PDF 需要解析文本层；DOCX 则需要读取主文档中的文字节点。不同格式提取出的结果可能存在排版差异。例如，PDF 中并排显示的两栏文字未必按预期顺序读出，扫描图片也可能完全提取不到文本。进入分块前应当先检查正文是否有意义。如果正文已经缺失或顺序错误，仅仅调整块大小不能恢复原始内容。

## 为什么需要分块

假设一份手册同时介绍账户管理、文件上传、模型调用和部署步骤。用户只询问文件上传时，我们希望找到介绍上传的几段文字，而不是把整份手册一起交给模型。分块提供了更细的检索单位。块太小可能缺少前提，例如留下“按照上面的方式处理”却丢失上面的规则；块太大又可能混入很多无关主题，因此块大小需要结合实际文档和问题进行实验。

## 重叠的作用

一条规则可能在块尾开始，到下一块开头才结束。为了降低边界处的信息丢失风险，可以让下一块重复上一块末尾的一小段文字。这段重复部分就是重叠。重叠不是新增内容，也不是模型生成的解释，它必须来自原文。如果重叠设置得太大，很多块会包含相似内容，增加后续存储和检索去重的工作，所以重叠并不是越大越好。

## 预览与正式索引

当前页面只展示一次分块实验的结果。调整参数不会写入数据库，也不会创建向量，更不会让聊天助手自动获得这些内容。正式检索还需要向量化、索引存储、知识库过滤和来源记录等步骤。若正文预览由于页数或字符上限被截断，分块只能覆盖已提取部分。完成本次实验时，请记录三组参数中哪组更容易阅读，再说明判断理由。
