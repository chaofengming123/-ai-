# 第 38 课之后的安排：先部署，再逐步完善

按用户要求，下一课先安排部署。第 39 课已实现本机 Docker 部署，见 [部署讲义](lesson-39.md)；公网部署尚未完成，也不代表已经具备正式生产运行条件。每课继续包含实现、关键代码的作用与执行顺序、验证步骤，以及 Git 提交和推送。

## 下一课：第 39 课，完整应用部署

当前仓库已经用 Docker Compose 运行 MySQL、MinIO、Qdrant 和 Redis，但 Vue 仍使用 Vite 开发服务，Spring Boot 仍通过本地启动脚本运行。第 39 课已补齐前后端应用镜像和 Nginx 配置。

下一课的目标是让整套应用通过一个网页入口运行，理解“开发启动”如何转成“部署运行”。当前采用本机 Docker 演练，后续可安排 Linux 服务器部署。没有服务器也可以先完成本机演练，再迁移到云端；课程不要求立即购买服务器。

计划按以下顺序实现：

1. 构建 Vue 静态文件，通过 Nginx 提供网页；解释为什么部署时不再使用 Vite 开发服务。
2. 打包 Spring Boot 并构建运行镜像；解释构建环境与运行环境、镜像与容器的区别。
3. 接入 Compose 网络。容器里的 `127.0.0.1` 指向容器自身，因此 MySQL、MinIO、Redis 和 Qdrant 的地址要改为服务名与容器端口；后端监听地址也要适配容器。
4. 用 Nginx 将 `/api` 转发到后端，处理 Vue 路由刷新、上传大小限制和流式回答的缓冲与超时。
5. 区分配置、密钥、镜像和数据卷。密钥不写入前端、镜像或 Git，数据不能只放在容器可写层。
6. 验证启动、停止、重启、查看日志和更新流程。确认登录、上传、索引、检索及流式回答可用，重建容器后数据仍在。

现有开发数据的复用或迁移需要明确处理，不能假设新 Compose 工程会自动使用旧数据卷。已有 Mac/Windows 共用数据的安排也应继续保持一个数据来源。

若选择公网服务器部署，还需处理域名、HTTPS、访问入口、备份和权限边界。数据库与存储管理端口不应直接作为公共访问入口。服务器和域名尚未确定时，先完成可本地验证的部署，不把公网可用写成已完成。

## 部署之后还能学习什么

| 方向 | 当前基础 | 后续可以实现与理解的内容 |
| --- | --- | --- |
| 部署维护 | 依赖服务已有 Compose，应用部署待补齐 | HTTPS、更新与回滚、数据备份与恢复演练、健康检查、配置分离 |
| 数据权限 | 已有登录和角色操作权限 | 用户只能访问授权知识库；列表、下载、索引和检索统一校验；检索前过滤权限 |
| 后台任务 | 进程内线程、状态、租约、有限重试 | 每次任务记录、开始结束时间、故障原因、持久化队列、重启恢复、幂等与并发控制 |
| 可观测性 | 已有 RAG 阶段耗时 | 请求标识、结构化日志、错误统计、任务监控、模型调用量与成本统计 |
| 文档处理 | 已有解析、分块、索引 | 大文档分页与批处理、OCR、表格提取、文档更新删除后的索引同步、孤立集合清理 |
| 检索质量 | 向量检索、字面关键词混合检索、BGE 重排 | 真正的全文或稀疏检索、检索阈值、分块策略对比、去重、多轮问题改写 |
| RAG 评估 | 已有来源标注、覆盖率与 RR 对照 | 固定测试题集、召回率、答案正确性与引用一致性、延迟与成本回归比较 |
| AI 安全 | 已有基础输入及响应校验 | 文档提示注入测试、敏感内容处理、越权检索测试、不足资料时的回答策略 |
| 自动化测试 | 已有前后端测试和构建 | 浏览器端到端测试、部署冒烟测试、故障注入、压力测试、CI 自动检查 |
| 产品体验 | 已有主要业务页面 | 任务历史、可理解的失败提示、搜索与分页、响应式布局、无障碍体验 |
| 后端基础深化 | 已有 Controller/Service/Mapper 实践 | 事务边界、SQL 索引与执行计划、锁与并发、连接池、HTTP 超时与幂等 |

这些是可选的深化方向，不是为了完成项目必须全部引入的新组件。特别是消息队列，应先明确任务可靠性需求，再决定是否需要；现有线程池的局限可以先通过测试理解。

## 建议的后续顺序

1. 第 39 课先完成部署，能启动、能观察故障、能保存数据。
2. 补充备份恢复和必要的数据权限边界。若要让其他真实用户访问，应优先完成这些内容。
3. 回到任务历史与可观测性，再讨论持久化调度。
4. 建立固定评估题集，用结果指导文档处理和检索优化。
5. 补齐端到端测试与持续集成，形成可重复交付的过程。

后续具体课号根据每课实际工作量安排。学习目标是能够说明每个改动解决什么问题、如何验证它有效，而不是只会复制配置并启动服务。
