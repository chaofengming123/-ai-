# 第 32 课：混合检索，让关键词补充向量候选

第 31 课可以判断有没有找回预期文档。这一课提供第二种检索方式：问题仍然做向量检索，同时按你输入的关键词查找已索引原文，最后融合两路排名。

## 一、先操作，再对比

1. 保持 MySQL、MinIO、Qdrant 运行，停止原后端后启动新版。只启动一份，避免 8080 冲突。
2. 打开文档管理，选中包含第 30 课两份练习文件的知识库，确认索引成功。
3. 输入“文本文件的编码有什么要求？”，标注预期文档 `upload-policy.md`。
4. 保持“向量检索”，点击查找，记录文档覆盖率、RR 和实际片段。
5. 切换为“混合检索”，关键词填 `UTF-8`，再次查找并对照。
6. 再试“单文件大小有什么限制？”，关键词填 `5 MB`。最后用不相关的关键词再查一次，观察排名是否变差。

两份很短的练习文件可能在两种方式下都命中，不能为了展示差异宣称混合检索必然更好。可用同一批较长资料、相同问题和固定标注继续比较。

本课没有数据库迁移，不需要重建同一模型配置下的有效索引，也不需要新模型密钥。关键词通道在后端处理原文，混合模式仍调用一次问题 Embedding；点击生成回答才额外调用 GLM。

## 二、两路检索分别做什么

向量检索比较语义接近程度，问题与资料可以用不同措辞。关键词通道检查字面是否出现，适合尝试编码名、产品型号、错误码等明确词语。

本课关键词是人工输入的 1–5 个词或短语，每个最多 40 个 UTF-16 字符。按英文或中文逗号分隔，去除两端空白、忽略大小写，重复词合并。

例如 `UTF-8` 能匹配 `utf-8`，但 `5MB` 不一定匹配 `5 MB`。这是子串匹配，不做中文分词、同义词扩展或词边界判断；关键词 `AI` 也可能出现在更长的英文字符串中。关键词重复出现十次不会比出现一次多得分。

关键词用于检索，会发送给后端；第 31 课的预期文档标注用于评估，仍只留在浏览器。这两类输入不能混淆。

## 三、完整执行顺序

```text
Vue：问题 + mode + keywords
  → Controller 绑定请求，Security 继续检查三项权限
  → Service 校验方式、关键词、问题
  → 查询当前库模型兼容的成功索引（最多 5 份）
  → 问题生成一次向量
  → 每份文档：向量 Top 3 + 扫描该成功版本的全部原文块
  → 向量候选统一排序（最多 15）
  → 关键词匹配候选排序（最多 15）
  → RRF 融合排名
  → 去掉完全相同原文，最多取 3 段，重新分配来源编号
  → 版本检查 → 返回片段，或继续 GLM 问答与最终校验
```

这里关键词通道会检查向量前三名以外的块，因此能够补充候选。如果只在向量前三名里搜关键词，就只能调整已有候选，无法找回被向量通道遗漏的块。

## 四、Controller 如何保持旧请求兼容

`KnowledgeBaseRagController.Query` 从只有 query 扩展为：

```java
public record Query(String query, String mode, List<String> keywords) {}
```

示例请求体：

```json
{"query":"文本文件的编码要求？","mode":"hybrid","keywords":["UTF-8"]}
```

没有传 mode 时，Service 默认使用 vector，旧客户端仍能使用原向量检索。未知方式返回 400；混合模式没有有效关键词也返回 400，在调用模型之前拒绝。向量模式忽略关键词。

成功响应增加 mode 与规范化后的 keywords，页面用返回值描述本次结果。用户后来切换下拉框，也不会把旧向量结果误标成混合结果。search 与 answer 两个接口均支持该参数。

## 五、如何从 Qdrant 取得关键词原文

`QdrantClient.scanDocument()` 调用 Scroll API，传入 `limit=12`、`with_payload=true`、`with_vector=false`。Scroll 用于分页读取点，payload 包含建立索引时写入的原文和来源信息；本课不下载向量数组。[Qdrant Scroll API](https://api.qdrant.tech/api-reference/points/scroll-points)

第 27 课已经限制单文档最多 12 块，因此一次读取的范围有明确上限。代码检查 `next_page_offset` 为 null，确认没有下一页，再检查实际块数等于 MySQL 已发布索引记录中的 chunkCount。缺块、额外分页或非法响应都会报错，不把第一页包装成完整扫描。

`DocumentSearchService.scanForKeywords()` 与向量路径共用后续来源检查：文档 ID、知识库 ID、模型空间、原文件摘要、发布版本、块编号与字符范围必须匹配。扫描完成还要核对当前发布版本。它只读 activeCollection，不读取未发布的重建数据。

扫描返回的内部 score 暂为 0，之后关键词通道重新评分；这个 0 不表示真实向量相似度。

最多五份文档、每份最多十二块，所以最多扫描六十块。这是受限教学实现，读取全部 payload 的方式不适合直接扩展到大规模语料。正式全文检索可以引入倒排索引、分词和 BM25；本课尚未实现这些机制，也没有使用稀疏向量模型。

## 六、关键词排名如何产生

`HybridRanking.fuse()` 对每个块计算命中的不同关键词数量：

```java
var text = hit.text().toLowerCase(Locale.ROOT);
long count = terms.stream().filter(text::contains).count();
```

`Locale.ROOT` 让大小写转换不依赖电脑语言设置。`contains()` 判断原文是否包含某个词；`filter()` 留下命中的词；`count()` 统计数量。零命中的块不进入关键词候选，命中数量越多越靠前。

同分时按文档 ID、块编号排序，随后保留前十五个关键词候选。这个简单计分不考虑词频、词的稀有程度或文档长度，不能称为 BM25。

## 七、为什么不直接把两个分数相加

向量相似度和关键词命中数量的尺度不同，直接相加会让较大的数值一方占优势。RRF（Reciprocal Rank Fusion）利用各路排名进行融合，不直接相加原始分数。Qdrant 也提供这一类融合能力；本课为便于理解，在 Java 中显式计算。[Qdrant 混合查询文档](https://qdrant.tech/documentation/search/hybrid-queries/)

本实现公式固定为：

```text
融合分数 = 向量路贡献 + 关键词路贡献
每一路贡献 = 1 / (60 + 该路排名)
排名从 1 开始；没出现在该路候选中则贡献 0。
```

例如 A 是向量第 1、关键词未命中，得到 `1/61 ≈ 0.01639`；B 是向量第 2、关键词第 1，得到 `1/62 + 1/61 ≈ 0.03252`，B 排在前面。

关键代码为：

```java
scores.merge(key, 1.0 / (60 + i + 1), Double::sum);
```

数组下标 i 从 0 开始，所以加 1 转为排名。`merge()` 在第一次遇到片段时记录分数，另一条路再次遇到同一片段时累加。key 使用“文档 ID + 块编号”，避免不同文档的第 0 块被混为一谈。

常数 60 是本课固定的教学参数，不表示当前 Qdrant 的默认配置或最优参数。RRF 舍弃了原始分差：两路都出现的片段会获得额外贡献，不相关关键词也可能把错误候选抬高。因此要使用评估结果和原文判断改动是否有益。

## 八、融合后为什么还需要去重和限长

两路各最多十五个候选，合并最多三十个片段身份。融合完成后，继续第 30 课的完全相同原文去重，再取三个片段供展示或生成回答。

身份融合按文档 ID 与块编号；原文去重按 text，两者作用不同。同一块出现在两路排名中要合并贡献；两个文件出现完全相同的段落则只保留排序在前的一份来源。

最终最多三段、每段最多八百字符，GLM 上下文原文上限仍是两千四百字符。去重后可能不足三段；关键词前十五名之外的候选不会自动补查。没有关键词命中时，融合仍保留向量候选的顺序，但显示的是转换后的融合分数。

混合模式的 score 是 RRF 分数，页面显示“融合分数”；向量模式的 score 仍是原相似度。两种分数不能直接比较大小，也都不是回答正确概率。

## 九、保留哪些失败与权限规则

只有当前知识库的兼容成功索引能参与。未索引或模型空间不兼容的文件继续明确列出，即使原文件含关键词，本课也不会绕过索引条件搜索它。

任一参与文档向量检索或扫描失败，整次请求失败，不自动退回部分结果。每份文档检查自己的版本，知识库处理结束及生成结束继续检查成员与发布版本，发生变化返回 409。

知识库查看、文档查看、AI 对话三项权限不变；并发、问题长度、上下文、引用编号和资料不足校验也继续沿用。关键词不是 system 指令，不会增加模型执行工具的能力。

混合路径增加了 Qdrant 读取次数，可能比原路径慢。前端仍等待最多 300 秒，Qdrant 每次调用有自己的超时；这些不是统一的服务端总截止时间。失败不自动重试，未新增跨请求缓存。
